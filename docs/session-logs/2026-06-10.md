# Session log — 2026-06-10

## What we worked on

Production chatbot was broken — every message returned an error.

## Diagnosis

Ruled out, in order:
- Static build: prod JS had the correct worker URL (`https://streameros-chatbot.yaseenyk.workers.dev/chat`) baked in, no localhost fallback — `NEXT_PUBLIC_CHAT_API` repo variable was set correctly.
- Worker deployment: reachable, healthy.
- CORS: preflight from `https://yaseenyk.github.io` passes.
- Retrieval: embedding + Upstash query worked (stream started before erroring).

Root cause: Google Gemini API key exhausted its free-tier daily quota. Prod errors:
"You exceeded your current quota, please check your plan and billing details" and
"This model is currently experiencing high demand."

## Fix

Switched the chat model from `gemini-flash-latest` to `gemini-flash-lite-latest`
(`api/src/index.ts:90`) — higher free-tier request-per-day limit. Deployed the
worker with `wrangler deploy` from `api/` and verified live: prod endpoint streams
a correct knowledge-base answer.

## Decisions made

- Chose model switch as the stopgap over waiting for quota reset or enabling
  billing. Billing on the Google project remains the durable fix if quota runs
  out again under load.

## Incident during deploy (resolved)

First deploy attempt ran `npx wrangler deploy` from the repo root instead of
`api/`. Wrangler detected the Next.js app and ran the OpenNext setup wizard,
which modified `package.json`, `package-lock.json`, `next.config.ts`,
`.gitignore` and created `wrangler.jsonc`, `open-next.config.ts`,
`public/_headers`, `.dev.vars`, `.open-next/`, `.wrangler/`. All reverted
(git checkout + file deletion + `npm ci`); only the intended one-line model
change remained. Lesson: deploy the worker from `api/`.
