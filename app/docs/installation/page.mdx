# Installation

streamerOS installs in minutes and connects to OBS Studio over **OBS WebSocket
v5** — the official control interface that ships inside OBS. There is no
account, no plugin, and no cloud service in the loop.

> 📅 streamerOS v1.0 launches **February 2027** for Windows.
> [Pre-register on the download page](/download) to get the release the day it ships.

## System requirements

- **OS:** Windows 10 or 11 (64-bit)
- **Memory:** 16 GB RAM
- **CPU:** 8 cores — the streamerOS core itself sustained about[1.8% CPU in the developer’s benchmark](/features/performance); the headroom is for your game, OBS, and the optional local AI
- **GPU:** RTX 3060-class (only needed for the local AI features)
- **OBS Studio** with its built-in WebSocket server (see step 1 below)

## Quick start

### 1. Enable the WebSocket server in OBS

In OBS Studio, open **Tools → WebSocket Server Settings** and enable the
server. This is OBS's own control interface — streamerOS talks to it over your
local machine only, so there are no third-party plugins to install.

### 2. Install streamerOS

streamerOS is not released yet: v1.0 is planned for February 2027, and people who
pre-register get the beta first. When it ships, the Windows build comes as two
installer formats, an `.exe` installer that installs for your Windows user only
(no administrator rights needed) and an `.msi` package for people who prefer that
format. Pick one; they install the same app.

The installer is not code-signed yet, so Windows SmartScreen may warn that the
publisher is unknown. The [trust page](/trust) explains how to check the file is
the real one before you run it. No account is created during setup, and there is
no sign-in screen when the app first opens. The 7-day trial starts on first launch
([how the trial and licence work](/docs#trial-and-licence)).

### 3. Connect to OBS

Launch streamerOS while OBS is running. On start-up, the
[OBS Bridge](/features/obs-bridge) probes OBS's default WebSocket address on your
own PC (`127.0.0.1`, port `4455`). One of three things happens:

- **OBS answers without a password.** streamerOS connects, loads your scene list
  and the current scene, and you can switch the program feed from the cockpit.
- **OBS asks for a password.** Recent OBS versions turn authentication on by
  default. streamerOS reports that a password is needed instead of failing
  silently. In OBS, open **Tools → WebSocket Server Settings → Show Connect Info**,
  copy the password, and paste it into the connection form in streamerOS.
- **Nothing answers.** OBS is closed, the WebSocket server is off, or it listens
  on a different port. Start OBS, check step 1, or enter the host and port by hand
  in the connection form. The automatic probe only ever tries the local address;
  the manual form is where you point it somewhere else.

### 4. Optional: local AI via Ollama

The AI features (AI Sidekick, chat sentiment) run on a local
[Ollama](https://ollama.com) install, nothing is sent to a cloud model. Install
Ollama for Windows and leave it running; streamerOS talks to it on your own PC at
`127.0.0.1:11434`. The default chat model is `llama3.2`, and the app's model
settings can download a model through Ollama and show the download progress, so
you do not have to use the command line. Skip this step if you only want
automation and telemetry: the rest of the app works without it, and the AI panels
show an offline notice when Ollama is not reachable.

### 5. Optional: YouTube subscriber count

YouTube Live chat is read from your own browser window, so no Google account or
API key is needed for chat. A YouTube Data API key is optional and only adds your
exact subscriber count. If you add one, it is stored in Windows Credential Manager,
not in the app's settings file.

## When something does not connect

| What you see | Most likely cause | What to do |
| --- | --- | --- |
| OBS asks for a password | OBS authentication is on (the default) | Copy the password from Show Connect Info in OBS and paste it in |
| OBS not found | OBS is closed or the WebSocket server is off | Start OBS, enable the server in Tools → WebSocket Server Settings |
| OBS not found, server is on | OBS uses a port other than 4455 | Enter the port shown in Show Connect Info in the manual form |
| AI panels say offline | Ollama is not running | Start Ollama; the app reconnects on its next request |
| SmartScreen warning | The installer is not code-signed yet | Check the file on the [trust page](/trust), then choose Run anyway |

For anything else, the [contact page](/contact) lists what to include in a bug
report.
